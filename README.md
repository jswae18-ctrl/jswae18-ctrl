# Hey, I'm Jason

I'm a C++ developer focused on graphics, engine development, low-level systems, and understanding how software actually works underneath the abstractions.

I first started getting into programming around January 2023. A lot of my early learning came from tutorials, experimenting with existing code, and using AI tools to help me figure out what I was looking at.

That got me comfortable reading code and following how larger systems fit together, but eventually I ran into a problem: I could get things working without always being able to explain why they were designed that way or rebuild the same idea on my own.

Around June 2026, I started changing how I approached learning.

Instead of measuring progress by whether I could get something to compile, I started slowing down and tracing what the code was actually doing: what owns the data, how long it lives, where it moves, what each system is responsible for, and why one design makes more sense than another.

I still use AI and documentation constantly. The difference is that I don't want either one doing the thinking for me. If I use something I don't understand, I break it down, rebuild it, debug it, and keep working with it until I can explain what's happening.

I'm comfortable reading and tracing C++ now, while continuing to work much deeper into algorithms, data structures, ownership, architecture, and writing solutions independently.

## What I'm Building

### Kinetic Aura Dynamics

My main project is **AuraDynamicsEngine**, a custom C++/DirectX 11 engine I've been developing while learning graphics and engine architecture at a much deeper level.

Current work includes:

- procedural sphere geometry
- custom HLSL rendering
- Sun-driven Earth lighting
- normal mapping and ocean specular
- night-side city lights
- animated clouds
- Earth rotation and orbital movement
- free-flight and moving-target camera systems
- custom keyboard and mouse input
- runtime HUD/editor tooling

The public repository is a working development checkpoint with real source, tests, screenshots, and recordings of the engine running.

## How I Use AI

AI has been part of how I've learned programming, and I don't try to hide that.

Early on, I leaned on it too heavily. It was easy to confuse being able to follow generated code with being able to design and implement the same system independently.

Realizing that changed the way I use it.

Now I use AI more like a tutor, debugger, reviewer, and second opinion. I ask why something works, pressure-test designs, trace failures, compare approaches, and use it to find gaps in my understanding.

But the code still has to make sense to me.

If I can't explain what something owns, why it exists, how the data moves through it, and what would break if I changed it, I don't consider myself finished learning it.
